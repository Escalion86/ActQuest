# Дизайн: вынос финансов игры в отдельную модалку

## Контекст

Сейчас финансы игры присутствуют в двух местах:

- в просмотре игры через `GameDescriptionModal`;
- в общем редакторе игры `GameEditModal`.

Это создаёт две проблемы:

- финансовый блок показывается в сценарии просмотра игры, где он не нужен;
- редактирование финансов связано с тяжёлой общей модалкой редактирования игры, хотя фактически это отдельный управленческий сценарий.

Дополнительно уже подтверждён инцидент с утечкой финансов через некоторые пути просмотра, поэтому финансовый UI нужно жёстко отделить от обычного просмотра игры.

## Цель

- Полностью убрать блок финансов из просмотра игры.
- Перенести управление финансами в отдельную модалку.
- Открывать новую модалку только с карточки игры.
- Показывать кнопку открытия только пользователям с правом управления игрой:
  - `admin`;
  - `dev`;
  - организатор игры;
  - модератор игры.

## Не меняем

- Не добавляем кнопку финансов внутрь просмотра игры.
- Не добавляем отдельный API только под финансы.
- Не переделываем общий поток сохранения игры.
- Не переносим финансы в отдельную серверную сущность.

## Выбранный подход

Выбран вариант с новой отдельной модалкой `GameFinancesModal`, которая использует существующий draft игры из `GamesPageClient`.

Причины выбора:

- минимальный риск регрессий;
- можно перенести уже существующий финансовый UI почти без изменений;
- не появляется второй источник истины для состояния игры;
- права доступа остаются в существующей модели управления игрой.

## Изменения в UI

### 1. Просмотр игры

Из `GameDescriptionModal` полностью удаляется секция `Финансы`.

Результат:

- обычный просмотр игры больше не содержит ни сводки финансов, ни списка записей;
- `UnifiedGameDescriptionModal` и все сценарии, которые его используют, автоматически перестают показывать финансы.

### 2. Карточка игры

На карточке игры в `GamesPageClient` добавляется новая action-кнопка `Финансы`.

Требования к кнопке:

- визуально соответствует соседним action-кнопкам карточки;
- круглая;
- с иконкой без текстовой подписи;
- получает понятный `title` / `aria-label`.

Кнопка рендерится только если текущий пользователь может управлять конкретной игрой. В текущем коде для этого используется существующая проверка `canManageGameStatus(game)`, которая уже покрывает `admin`, `dev`, организатора и модератора игры.

### 3. Новая модалка финансов

Добавляется `components/modals/GameFinancesModal.js`.

Содержимое модалки:

- заголовок `Финансы игры — <название>`;
- кнопка добавления записи;
- список финансовых записей;
- редактирование полей записи:
  - тип (`income` / `expense`);
  - дата;
  - сумма;
  - описание;
- удаление записи;
- сводка:
  - доходы;
  - расходы;
  - баланс;
- пустое состояние, если записей нет.

UI и логика списка финансов переносятся из текущего блока `GameEditModal` максимально буквально, без переосмысления полей.

## Состояние и поток данных

Источником данных остаётся `GamesPageClient`.

План работы состояния:

- добавить `isFinancesModalOpen`;
- добавить `handleOpenFinancesModal(game)`;
- при открытии модалки поднимать `selectedGameId`;
- если для игры ещё не создан draft в `editingGame`, создавать его из выбранной игры так же, как это уже делается для других сценариев редактирования;
- модалка работает с тем же `editingGame` / `modalGame`, что и существующий редактор.

Это даёт:

- единое состояние игры;
- отсутствие рассинхронизации между общим редактором и финансами;
- повторное использование существующих обработчиков:
  - добавление записи;
  - изменение записи;
  - удаление записи;
  - вычисление `financesSummary`.

## Сохранение

Отдельный серверный endpoint не вводится.

Изменения финансов попадают в тот же draft игры, что и остальные поля. Сохранение остаётся в текущем механизме сохранения игры из `GamesPageClient`.

Следствие:

- логика `unsaved changes` остаётся общей;
- новая модалка не требует отдельного мутационного потока;
- после сохранения игры финансы фиксируются штатно вместе с остальными данными draft.

## Права доступа

Права на кнопку и модалку определяются существующей проверкой управления игрой:

- `admin` и `dev` имеют доступ всегда;
- организатор игры имеет доступ;
- модератор игры имеет доступ;
- обычный пользователь без этих ролей кнопку не видит.

Серверная защита финансов уже должна оставаться отдельным слоем и не зависит от UI-кнопки.

## Технические изменения по файлам

- `components/modals/GameDescriptionModal.js`
  - удалить секцию финансов;
  - убрать связанные `props`, которые больше не используются.

- `components/modals/UnifiedGameDescriptionModal.js`
  - убрать вычисление `financesSummary`;
  - убрать передачу финансовых `props` в `GameDescriptionModal`.

- `components/modals/GameEditModal.js`
  - удалить встроенный блок редактирования финансов;
  - сохранить только общие части редактора игры.

- `components/modals/GameFinancesModal.js`
  - новый компонент с перенесённым UI финансов.

- `components/modals/GameModals.js`
  - подключить новую модалку;
  - прокинуть нужные `props`.

- `components/cabinet/app-router/GamesPageClient.js`
  - добавить состояние открытия модалки финансов;
  - добавить обработчик открытия с карточки;
  - добавить кнопку на карточки игр;
  - прокинуть в `GameModals` нужные `props`.

## Ошибки и граничные случаи

- Если игра не выбрана, модалка финансов не открывается.
- Если у игры нет финансовых записей, показывается пустое состояние без ошибок.
- Если пользователь не имеет прав, кнопка отсутствует, а модалка не должна открываться через UI.
- Если draft уже существует и содержит несохранённые изменения, модалка финансов должна использовать именно его, а не пересоздавать состояние из persisted-версии игры.

## Проверка

Минимальная проверка после реализации:

- блок финансов отсутствует в просмотре игры;
- кнопка финансов видна только на карточке игры;
- обычный пользователь без прав кнопку не видит;
- организатор игры кнопку видит;
- модератор игры кнопку видит;
- `admin`/`dev` кнопку видят;
- добавление, редактирование и удаление финансовых записей продолжают работать;
- линт проходит по новым и затронутым файлам.

## Риски

- `GamesPageClient` уже большой, поэтому важно не дублировать существующую логику draft;
- при переносе блока из `GameEditModal` легко оставить старые `props` и вычисления мёртвыми;
- если неаккуратно развести `selectedGame` и `editingGame`, можно получить визуальную рассинхронизацию после открытия модалки финансов.

## Рекомендация по реализации

Двигаться в таком порядке:

1. создать `GameFinancesModal`;
2. подключить её в `GameModals` и `GamesPageClient`;
3. добавить кнопку на карточки;
4. убрать финансы из просмотра игры;
5. убрать старый финансовый блок из `GameEditModal`;
6. прогнать линт и точечные проверки.
