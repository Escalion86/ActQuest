# Дизайн распределения заданий по командам

Дата: 2026-06-29

## Цель

Добавить в web/cabinet-ветку ActQuest возможность выдавать задания командам в индивидуальном порядке:

- линейно, как сейчас;
- случайно внутри заданных блоков;
- по индивидуальному шаблону конкретной команды;
- с ручным перераспределением до старта и частичным перераспределением после старта без изменения уже начатых заданий.

Интерактивные результаты и статистика должны оставаться привязанными к исходному порядку `game.tasks`, чтобы результат задания 2 всегда отображался в столбце задания 2, даже если команда проходила его первым.

## Термины

- Исходный индекс задания - индекс задания в `Games.tasks`.
- Шаг команды - позиция команды в индивидуальном маршруте прохождения.
- Шаблон распределения - блоки исходных номеров заданий, например `[1,2,3],[4,5],6,[7,8]`.
- Последовательность команды - зафиксированный маршрут исходных индексов, например `[2,0,1,4,3,5,7,6]`.

## Данные

В `Games` добавляются поля:

- `taskDistributionMode`: строка `'linear' | 'random'`, по умолчанию `'linear'`.
- `taskDistributionTemplate`: массив блоков исходных индексов заданий. UI-структура `[1,2,3],[4,5],6,[7,8]` хранится как `[[0,1,2],[3,4],[5],[6,7]]`.

В `GamesTeams` добавляются поля:

- `taskDistributionTemplate`: индивидуальный шаблон команды, опционально.
- `taskSequence`: зафиксированная последовательность исходных индексов заданий.
- `taskSequenceGeneratedAt`: дата генерации.
- `taskSequenceSource`: `'game_template' | 'team_template' | 'linear'`.

`activeNum` остается номером шага команды. Активный исходный индекс задания вычисляется через helper:

```js
activeTaskIndex = taskSequence[activeNum] ?? activeNum
```

Все массивы прогресса (`startTime`, `endTime`, `findedCodes`, `wrongCodes`, `findedBonusCodes`, `findedPenaltyCodes`, `photos`, `forcedClues`, `taskFailures`) индексируются исходным индексом задания, а не шагом команды.

## Валидация шаблонов

Общий helper распределения должен уметь:

- нормализовать шаблон из UI/JSON/массива;
- проверять шаблон относительно текущего количества заданий;
- генерировать последовательность команды.

Правила валидации:

- номера заданий должны быть целыми;
- допустимый диапазон в UI: `1..tasksCount`;
- внутри приложения используется диапазон `0..tasksCount-1`;
- каждое задание должно присутствовать ровно один раз;
- дубли запрещены;
- пропуски запрещены;
- номера вне диапазона запрещены;
- пустые блоки запрещены;
- при `tasksCount === 0` случайное распределение недоступно.

Примеры сообщений:

- `В шаблоне отсутствуют задания: 7, 9`
- `В шаблоне указаны несуществующие задания: 11`
- `Задание 3 указано несколько раз`
- `В шаблоне есть пустой блок`

## Генерация последовательности

Кнопка `Распределить задания`:

- для каждой команды берет `gameTeam.taskDistributionTemplate`, если он задан;
- иначе берет `game.taskDistributionTemplate`;
- валидирует выбранный шаблон;
- перемешивает задания только внутри каждого блока;
- сохраняет итоговую `taskSequence` в `GamesTeams`.

Если команда имеет индивидуальный шаблон, используется он. Если индивидуального шаблона нет, используется общий шаблон игры.

Если администратор изменил индивидуальный шаблон команды после общего распределения, для этой команды нужно повторно нажать `Распределить для команды`. До этого команда считается требующей перераспределения.

## Правила после старта

После старта игры уже начатые задания команды жестко фиксируются.

При повторном распределении после старта:

- helper определяет исходные задания с прогрессом через `startTime`, `endTime`, найденные коды, фото и `taskFailures`;
- зафиксированный префикс последовательности не меняется;
- новая генерация применяется только к еще не начатым заданиям;
- если новый шаблон конфликтует с уже зафиксированными заданиями, API возвращает ошибку с перечислением конфликтов.

## Блокировка старта

Если `taskDistributionMode === 'random'`, старт игры должен быть заблокирован, пока у каждой команды нет валидной `taskSequence`.

Это серверный инвариант, а не только UI-проверка. При попытке старта возвращается ошибка:

`Сначала распределите задания для всех команд`.

## Игровой процесс

Нужны helper-функции:

- `getTeamTaskSequence(game, gameTeam)` - возвращает валидную последовательность или линейный fallback.
- `getTaskIndexForStep(game, gameTeam, step)` - возвращает исходный индекс задания для шага.
- `getStepForTaskIndex(gameTeam, taskIndex)` - возвращает шаг команды для исходного задания.
- `getLockedTaskSequencePrefix(gameTeam)` - возвращает уже начатые исходные задания, которые нельзя переставлять.

Изменяем web-ветку:

- `server/webGameProcess.js`: активное задание берется через `taskSequence[activeNum]`; прогресс пишется в массивы по исходному индексу задания.
- `server/getTeamGameTaskState.js`: перерывы, подсказки, капитанский провал, post-message и автопереходы используют активный исходный индекс, а `activeNum` двигают как шаг.
- `app/api/webapp/game-task/route.js`: контракт можно расширить метаданными активного задания без изменения базового запроса.
- `app/api/cabinet/admin/game-status/action/route.js`: `apply_code`, `force_complete`, `force_fail` работают с активным исходным индексом, но продвигают команду на следующий шаг.

## Game Control

`app/api/cabinet/admin/game-status/route.js` должен возвращать для команды:

- `activeTaskStep`;
- `activeTaskIndex`;
- `currentTaskTitle`;
- `taskSequence`;
- `taskSequenceLabels`;
- `teamProgressStats.tasks` в исходном порядке `game.tasks`.

В UI Game Control желательно показывать формат:

`Шаг 2/10: задание 5. Название`

Так администратор видит и маршрут команды, и исходный номер задания.

## UI редактора игры

В редактор игры добавляется блок `Распределение заданий`:

- выбор `Линейное` / `Случайное`;
- при `Линейное` показывается подсказка, что задания выдаются в порядке редактора;
- при `Случайное` показываются текущий шаблон, кнопка `Конструктор блоков` и описание формата.

Описание формата:

`Квадратные скобки перемешиваются внутри блока, блоки идут по порядку. Пример: [1,2,3],[4,5],6,[7,8]`.

Модалка конструктора:

- список заданий с номерами и названиями;
- блоки с заданиями;
- действия добавления, удаления и перемещения заданий между блоками;
- live-предпросмотр строки шаблона;
- live-валидация пропусков, дублей и лишних номеров;
- сохранение доступно только для валидного шаблона.

## UI редактора команд

В редакторе команд на игре для каждой команды показывается:

- источник шаблона: общий шаблон игры или индивидуальный шаблон;
- текущий зафиксированный маршрут, если он уже распределен;
- статус `требуется перераспределение`, если индивидуальный шаблон изменен после генерации;
- кнопки `Изменить шаблон`, `Сбросить индивидуальный шаблон`, `Распределить для команды`.

Если часть заданий уже начата, эти задания показываются как зафиксированные и недоступные для перестановки.

## UI перед стартом

Для случайного режима перед стартом показывается кнопка `Распределить задания`.

После успешного распределения показывается статус:

`Распределено для N команд`.

Если распределение неполное, `Запустить игру` должно получить серверную ошибку. UI может дополнительно отключать или предупреждать, но серверная проверка обязательна.

## Результаты

`server/buildGameResultComputed.js` должен считать длительности и корректировки по исходным индексам заданий.

Инварианты:

- `taskResults[taskIndex]` относится к `game.tasks[taskIndex]`;
- `taskBoards` строится в порядке `game.tasks`;
- интерактивная таблица результата остается в порядке редактора заданий;
- `computed.teams[].taskSequence` можно добавить как справочную информацию, но нельзя использовать как порядок столбцов.

## Совместимость

- Старые игры без `taskDistributionMode` считаются линейными.
- Старые `GamesTeams` без `taskSequence` работают линейно.
- Telegram legacy не расширяется новой механикой; схема не должна его ломать.
- Для `story` распределение скрывается или игнорируется, так как story-движок использует отдельную модель.

## Проверки

Unit/smoke проверки helper-а:

- линейный fallback;
- перемешивание внутри блоков при сохранении порядка блоков;
- дубли;
- пропуски;
- несуществующие номера;
- пустые блоки;
- индивидуальный шаблон команды перекрывает общий шаблон игры.

Серверные проверки:

- старт случайной игры без `taskSequence` блокируется;
- распределение создает `taskSequence` для всех команд;
- повторное распределение после старта не меняет уже начатые исходные задания.

Ручная проверка:

- команда получает задания в индивидуальном порядке;
- Game Control показывает текущий исходный номер задания;
- `force_complete` и `force_fail` двигают команду на следующий шаг;
- результат показывает данные задания 2 в столбце задания 2, даже если команда проходила его первым.
