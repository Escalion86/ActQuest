# Копирование заданий в другую игру

В кабинете откройте редактор заданий исходной игры → «Открыть настройки» →
«Скопировать задания в другую игру». Источник может быть завершён или закрыт:
нужно право видеть его секретное содержимое (admin/dev, организатор либо
назначенный модератор). Простая публикация заданий для игроков такого права
не даёт. Если есть несохранённые изменения, сначала предлагается явно сохранить
их; при отмене или ошибке сохранения переход к копированию не происходит.

1. Отметьте отдельные задания или «Выбрать все». При пустом выборе продолжение
   недоступно. Наборы с неподдерживаемыми зависимостями показывают причину отказа.
2. Выберите игру назначения. Список содержит только доступные для редактирования
   `active`-игры того же типа и города; исходная игра исключена. `started`,
   `finished`, `closed`, `canceled` исключены независимо от плановой даты.
3. Подтвердите название игры и количество заданий. Копии добавляются в конец
   в порядке исходной игры, независимо от порядка кликов по чекбоксам.
4. Дождитесь ответа сервера. После успеха можно открыть редактор заданий цели;
   он получает свежую игру, даже если её нет в текущей странице/фильтре списка.

Существующие задания, таймеры, оформление и остальные настройки цели сохраняются.
Коды, фотографии кодов, rich text, подсказки, подзадачи, бонусы/штрафы, координаты
и медиа сохраняются; медиа ссылаются на те же файлы. Идентификаторы заданий,
вложенных сущностей и `stageKey` создаются заново. Изменение текста копии не меняет
источник. Назначения агентов очищаются; новые права в цели не выдаются.

Копирование доступно для `classic` и `photo`. `storyNodes/storyEdges` не являются
`tasks`: этот сценарный граф не переносится. Задания с вариантами (включая
сохранённые выключенные варианты), наградами предметами или исходами блокируются
с конкретной причиной: условия содержат ссылки на `classicItems`, `stageId`,
`variantId`, предыдущие коды/исходы. Простые независимые задания из игры с
каталогом предметов копировать можно. Для переноса связанных наборов используйте
существующее копирование игры целиком.

## API и конкурентные запросы

`GET|POST /api/cabinet/games/[gameId]/copy-tasks` использует настоящую серверную
сессию NextAuth; роли/содержимое заданий из тела запроса не принимаются.

- GET возвращает только `{ tasks: [{ id, title, blockedReason }], targets }`,
  без кодов и секретных текстов. Проверка прав выполняется и на чтении.
- POST: `{ targetGameId, taskIds, requestId }`. `taskIds` — сохранённые MongoDB
  `_id` заданий, а не временные `id` редактора. Содержимое заново читается из БД.
- Успех: `{ success: true, data: { targetGameId, count } }`.
- Права обеих игр, город, тип и статус назначения проверяются сервером. Перед
  повтором проигранной записи заново читаются источник и назначение.
- `$push.tasks` и квитанция `taskCopyOperations` записываются одной атомарной
  операцией. CAS сравнивает прежние задания, настройки распределения, права,
  статус и timestamp, не перезаписывая конкурентные задания; до пяти попыток.
- `requestId` сохраняется в открытой модалке для повторов после ошибки. Та же
  операция добавляет задания один раз; другой набор с тем же ключом даёт 409.
  Квитанции исключены из обычной Mongoose-проекции, публичных ответов и diff
  истории; полный snapshot сохраняет их для согласованного rollback.
- Общий random-шаблон атомарно получает новые одиночные блоки в конце.
  Существующие блоки и порядок внутри них сохраняются. Индивидуальные шаблоны
  и подготовленные маршруты команд дополняются CAS-записями, сохраняя прежний
  префикс, источник и метаданные маршрута. До добавления повреждённое
  распределение отклоняется с объяснением.
- Запись истории (`game_updated`, «Скопировано заданий: N») содержит snapshot
  целевой игры и команд; детерминированный ID защищает историю от дублей.
- Атомарность добавления относится к документу игры. Синхронизация `GamesTeams`
  и запись истории выполняются после него без MongoDB-транзакции. При обрыве
  сервер отвечает 503 с явным сообщением, что задания уже добавлены; повтор с
  тем же ключом завершает маршруты/историю без повторного добавления. До
  завершения этих действий UI не показывает успех. Не создавайте новый запрос
  вместо предложенного повтора при таком ответе.

## Проверки

```sh
node --no-warnings --test scripts/copyGameTasks.test.mjs scripts/copyGameTasks.ui.test.mjs
```

Это реальные handlers/JSX через Next SWC и настоящий Mongoose casting с
контролируемыми моделями БД и сессией. Подключения к рабочей MongoDB нет.
Покрыты доступ, статусы/город/тип/ID, порядок/содержимое/новые идентификаторы,
дубли/гонки, история, random-шаблоны и маршрут, dirty-save и шаги интерфейса.

Для браузера (нужен уже установленный Playwright/Chromium):

```sh
COPY_TASKS_QA_OUTPUT=/absolute/scratch/actquest-copy-qa/browser node scripts/copyGameTasks.browserHarness.mjs
COPY_TASKS_QA_OUTPUT=/absolute/scratch/actquest-copy-qa/browser COPY_TASKS_PLAYWRIGHT_MODULE=/path/playwright/index.mjs COPY_TASKS_CHROMIUM_PATH=/path/chrome node scripts/copyGameTasks.browser.mjs
```

Стенд на `http://127.0.0.1:3295` использует настоящий JSX редактора, настроек и
копирования, Modal/CabinetButton и CSS; API и не относящиеся к сценарию тяжёлые
дочерние редакторы заменены фикстурами. Проверки охватывают 390/1440 px,
светлую/тёмную темы, закрытый источник, все шаги, отказ/повтор, двойной клик,
ожидание ответа, dirty-save, пустой источник и story. Все артефакты остаются в
указанном scratch-каталоге. Остановка: POST `/__stop` на localhost-стенд.
