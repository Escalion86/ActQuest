# App Router Smoke Checklist

Дата: 2026-04-04

Цель: ручной контроль ключевых пользовательских сценариев после полного перехода на `app`/`app/api`.

## 1. Авторизация и сессия

1. Открыть `/cabinet/login`, войти под dev/admin.
2. Проверить редирект на `callbackUrl` (если задан) и на `/cabinet` по умолчанию.
3. Обновить страницу (`F5`) на:
   - `/cabinet/games-upcoming`
   - `/cabinet/games-past`
   - `/cabinet/admin/users`
4. Убедиться, что сессия сохраняется и нет разлогина.

Ожидаемый результат:
- нет перехода на `/cabinet/login` при валидной сессии;
- роль/аватар и данные пользователя не теряются.

## 2. Кабинет игр

1. Открыть `/cabinet/games-upcoming` и `/cabinet/games-past`.
2. Проверить фильтры (город, сезон, отменённые для admin/dev).
3. Открыть карточку игры, затем модалку просмотра и редактирования.
4. Для доступной игры проверить регистрацию команды/отмену регистрации.

Ожидаемый результат:
- список грузится стабильно после client-nav и после refresh;
- модалки открываются без ошибок в консоли;
- действия не ломают состояние страницы.

## 3. Команды и профиль

1. Открыть `/cabinet/teams` и `/cabinet/profile`.
2. В профиле проверить:
   - изменение профиля;
   - изменение номера телефона (start/check/finalize);
   - переключение push.
3. В командах проверить:
   - создание/редактирование/просмотр;
   - удаление команды капитаном с ограничениями.

Ожидаемый результат:
- API-ошибки показываются человекочитаемо;
- обновления данных видны без ручного очищения кэша.

## 4. Админка

1. Открыть:
   - `/cabinet/admin/users`
   - `/cabinet/admin/teams`
   - `/cabinet/admin/transactions`
   - `/cabinet/admin/reports`
2. Проверить фильтрацию/поиск и открытие модалок просмотра.
3. Проверить отправку user push (для тестового пользователя).

Ожидаемый результат:
- списки загружаются при переходе и после refresh;
- модалки единообразны и клики по карточкам работают.

## 5. API базовые проверки

Проверить вручную в браузере/REST-клиенте:
- `GET /api/health`
- `GET /api/public/site-access?location=krsk`
- `GET /api/cabinet/games-list?...` (с валидной сессией)

Ожидаемый результат:
- единый формат ответов (`success`, `data`/`error`);
- корректные HTTP статусы.

## 6. Наблюдаемость

1. Проверить серверные логи при login/refresh на страницах кабинета.
2. Убедиться, что нет повторяющихся ошибок импорта node-only модулей в browser bundle.
3. Отслеживать минимум 24 часа на dev/prod:
   - рост 401/403/500 по `/api/cabinet/*`;
   - частоту logout после refresh;
   - ошибки WebSocket/HMR в dev (для локальной диагностики).

## Финальный чек

- `npm run premerge:app` проходит локально.
- Критичных регрессий из разделов 1-6 не обнаружено.
