# Активные предметы classic

Реализация web/cabinet от 2026-11-04. Предмет можно выдать за основной,
бонусный или штрафной код, за выполнение/провал этапа либо выбранного варианта.
Полученный предмет остаётся в инвентаре команды и применяется позже.

В редакторе заданий включите предметы и варианты, откройте каталог предметов,
задайте эффект и при необходимости разрешённые задания. Если список заданий
пуст, предмет доступен на любом активном задании. Название и описание предмета
видны до применения; текст и изображение скрытой помощи задаются отдельно.

| Эффект | Поведение |
| --- | --- |
| Телепорт во времени (`time_rewind`) | Уменьшает игровое и зачётное время на заданную длительность. Требуется, чтобы столько времени уже прошло. Будущие подсказки сдвигаются, открытые остаются. По умолчанию 5 минут. |
| Песочные часы (`time_freeze`) | Останавливает часы задания и будущие подсказки на заданное время. По умолчанию 2 минуты. Если задание завершено раньше, учитывается только использованная часть паузы. Одновременные заморозки запрещены. |
| Хрустальный шар (`free_clue`) | Открывает следующую обычную подсказку без штрафа и перевода часов. После последней подсказки недоступен. |
| Тайное послание (`secret_clue`) | Открывает отдельный текст и/или изображение организатора. Не меняет расписание обычных подсказок. |
| Щит (`penalty_shield`) | Защищает от следующего штрафа за штрафной код или сформированный лимит неверных вводов на текущем задании. Один щит нейтрализует один штраф. Не защищает от провала и досрочной подсказки. Не переносится на следующий этап. |
| Ластик (`penalty_erase`) | Снимает один выбранный штраф за код или подбор текущего задания. Уже нейтрализованные штрафы недоступны. |
| Отмычка (`lockpick`) | Закрывает один недостающий обязательный код. Если это последний необходимый код, завершает задание. Правильный ответ не раскрывается, награда за ввод этого кода не выдаётся. |
| Компас (`compass`) | Показывает подготовленный организатором ориентир: текст и/или изображение. Для разных заданий создавайте отдельные предметы с ограничением применения. |
| Портал (`portal`) | Успешно завершает текущее задание без решения. Выдаёт обычные награды за выполнение и запускает обычный перерыв; штраф за провал не начисляется. |

Капитан применяет предмет из инвентаря после подтверждения. Тратится одна единица.
Для уникального предмета в инвентаре бывает не больше одной единицы.
Применение разрешено только в запущенной игре, после выбора пути, до завершения,
слива или таймаута задания. Во время перерыва применение недоступно. Полномочия,
наличие предмета и условия эффекта проверяет сервер. Одна и та же скрытая помощь
от одного предмета открывается на этапе только один раз; результат доступен
всем участникам команды после обновления экрана.

## API и сохранение

`POST /api/webapp/game-task`:

```json
{
  "location": "krsk",
  "gameId": "…",
  "teamId": "…",
  "action": "useItem",
  "stageId": "…",
  "itemId": "…",
  "requestId": "UUID",
  "penaltyKey": "code:…"
}
```

`penaltyKey` нужен только ластику и выбирается из `inventory[].penalties`.
`requestId` сохраняется при повторе запроса. Повтор успешного применения
не расходует вторую единицу; подмена предмета, этапа или цели с тем же ID
отклоняется. Все изменения проходят под общей блокировкой команды и сохраняются
одним обновлением `GamesTeams`. Размер бонуса и содержимое помощи берутся
из сохранённой игры. Публичный инвентарь содержит только тип и длительность
эффекта; скрытые текст и изображение выдаются в `itemHelp` после применения.

Настройка эффекта хранится в `classicItems[].effect`: `type`, `seconds`
для временных эффектов, `text` и `image` для скрытой помощи, `allowedStageIds`.
Изображение допускает только HTTP(S). Предметы без эффекта продолжают работать
как награды, условия и расход при выборе пути.

## Часы и результаты

Телепорт и заморозка создают отрицательные `timeAddings` со scope
`task_elapsed`, источниками `item_time_rewind` и `item_time_freeze`.
Эти значения уже включены в длительность задания и повторно из итога
не вычитаются. Заморозка накапливается по фактически прошедшим секундам;
при завершении этапа сохраняется использованная часть. Платная досрочная
подсказка продолжает сдвигать игровое время вперёд даже во время заморозки.
Проваленное задание получает полный собственный лимит времени.

Щит и ластик сохраняют исходные штрафные коды, неверные вводы и штрафы.
Компенсация записывается отдельным отрицательным `timeAddings` со scope
`total_adjustment`, источником `item_penalty_shield` или `item_penalty_erase`.
Ключи нейтрализованных штрафов хранятся в `classicProgress.stages[].waivedPenalties`;
повторное снятие того же штрафа невозможно. Компенсация вычитается из итога один раз.

Отмычка хранит отдельный счётчик `virtualCodes`, не подделывая введённые коды.
Портал и завершающая отмычка сохраняют `completionSource`.
Все применения журналируются как `item_used`, срабатывание щита — `penalty_blocked`.
Экран команды, Game Control, подробная статистика и таблица/анимация результатов
используют эти данные. В результате доступны `realSeconds`, `seconds`,
`timeBonusSeconds`, `itemBonusSeconds`, `itemEffects`, `virtualCodesCount`
и `completionSource`. Новый старт очищает эффекты и прогресс предметов.

Капитанские `forceClue`, `failTask` и `finishBreak` в движке предметов требуют
`stageId`. Экран запоминает его при открытии подтверждения: обновление задания
в другой вкладке или применение портала другим капитаном не перенаправляет
старое подтверждение на новый этап. Запрос без этапа получает 400, со старым — 409.
При нулевом перерыве это предотвращает повторное завершение и перескок задания.

Game Control использует тот же знаковый итог, что и результат: бонусные коды
могут сделать итог отрицательным, даже когда игровое время откатилось к нулю.
Задание без лимита не считается завершённым по часам. Его явный провал всё равно
получает штраф и признак `isFailedTask`; таблица результатов не выдаёт ему награду
за лучшее время.

Общие и индивидуальные лимиты/расписания описаны в [task-timing.md](task-timing.md).
Альтернативы используют время своего этапа.

## Проверки

`npm run test:classic-game-process` покрывает девять эффектов, реальные API handlers
с контролируемыми БД/сессией, права, скрытие помощи, повторные и параллельные
запросы, сочетания временных эффектов, награды и расчёт итогов.
`scripts/classicItemCombinations.test.js` перебирает все 40 320 порядков восьми
незавершающих эффектов перед порталом; для каждого порядка сверяет перерыв,
начало следующего этапа, расход и однократные награды. Полный расчёт результата
проверяется на выборке из 120 порядков. Дополнительно
проверяются 10 000 действий в 100 воспроизводимых последовательностях,
завершение кодом/отмычкой/порталом, слив и таймаут, а также сохранение этапа
в настоящих обработчиках подтверждения капитанских действий.
API-проверки с контролируемыми часами сверяют экран команды, Game Control
и результат после всех девяти эффектов; проверяют гонку завершающих действий,
двух ластиков, повторы, сбой записи и повтор, остановку во время заморозки,
нулевой лимит и отрицательный итог.
`scripts/taskCountdowns.test.js` проверяет серверные отметки и настоящий эффект
обновления клиентских таймеров во время и после заморозки.
Браузерный стенд проверяет редактор, инвентарь, подтверждение и статистику
на экранах 390 и 1440 px. Стенд использует настоящие компоненты и движок.
Авторизованный прогон с реальной MongoDB остаётся отдельной проверкой.
