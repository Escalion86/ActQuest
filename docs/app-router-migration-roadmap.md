# App Router Migration Roadmap (ActQuest)

## Легенда статусов

- [x] Выполнено
- [~] В процессе
- [ ] Не начато

Дата создания: 2026-04-03.

## Цель

Постепенно перевести проект с `pages` router на `app` router без простоя и без массовых регрессий в кабинете, API и авторизации.

## Ограничения и правила миграции

- Не делать «big bang» миграцию.
- Держать `pages` и `app` параллельно до полного переноса.
- Переносить маршруты вертикальными срезами: UI + данные + API.
- Для чувствительных зон (`/cabinet`, auth, games) сначала делать пилот и наблюдаемость.

## Этапы

### Этап 0. Подготовка инфраструктуры

- [x] Создать базовый `app`-каркас (`app/layout.js`, `app/globals.css`).
- [x] Добавить пилотную страницу в `app` без конфликтов с существующими роутами.
- [x] Добавить первый route handler в `app/api` без конфликтов.
- [ ] Включить обязательный smoke-check для app-роутов в pre-merge.

### Этап 1. Базовые публичные страницы

- [~] Перенести не-критичные публичные страницы в `app/*` (пилот: `/legacy-pilot`, чтобы не конфликтовать с `pages/legacy`).
- [ ] Убрать дубли стилей/метаданных между `_app/_document` и `app/layout`.
- [ ] Проверить SEO-метаданные после переноса.

### Этап 2. Auth в App Router

- [~] Подготовить shared-конфиг auth (`authOptions`) вне `pages/api` для совместного использования в `pages` и `app`.
- [ ] Перенести `NextAuth` в `app/api/auth/[...nextauth]/route.js`.
- [ ] Сохранить совместимость callbackUrl и текущих flows (`login/register/recovery`).
- [ ] Убрать временные compatibility-хаки в `pages/api/auth`.

### Этап 3. Cabinet маршруты (по одному)

- [~] Добавить пилот read-only команд в app (`/cabinet-app/teams`) с SSR-auth и загрузкой команд текущего пользователя.
- [ ] Перенести `/cabinet/games-upcoming` в `app`.
- [ ] Перенести `/cabinet/games-past` в `app`.
- [ ] Перенести `/cabinet/profile`, `/cabinet/teams`.
- [ ] Перенести admin-разделы (`users`, `teams`, `reports`, `transactions`).

### Этап 4. API миграция

- [~] Перенести `pages/api/cabinet/*` в `app/api/cabinet/*` (старт через pilot endpoint `app/api-pilot/cabinet/teams/route.js`).
- [ ] Перенести `pages/api/phone/*`, `pages/api/public/*`.
- [ ] Сверить коды ошибок/контракты ответов (без breaking changes для frontend).

### Этап 5. Декомиссия Pages Router

- [ ] Удалить дублирующиеся `pages` маршруты после стабилизации.
- [ ] Удалить legacy-обвязку (`_app`, `_document`) после полного переноса.
- [ ] Финальный регресс-прогон ключевых сценариев (auth, games, teams, admin).

## Критерии готовности к cutover

- [ ] Все пользовательские и админские маршруты работают из `app`.
- [ ] Все API-контракты сохранены или согласованно обновлены.
- [ ] Нет критичных регрессий по авторизации, сессиям и SSR/refresh сценариям.
- [ ] Логи и мониторинг подтверждают стабильность в течение контрольного окна.
