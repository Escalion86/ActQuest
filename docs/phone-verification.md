# Подтверждение телефона: звонок и СМС

Глобальный `SiteSettings.phoneVerificationPrimaryMethod` принимает `call` или
`sms`. Отсутствующее и некорректное значение означает `call`. Переключатель
«Приоритет подтверждения телефона» находится в разделе разработчика рядом
с настройкой ИИ. Выбор меняется после подтверждения сервера; ошибки загрузки
и сохранения допускают повтор. Выключенный `allowSmsVerification` всегда
оставляет звонок первым, что поясняется у переключателя.

`PATCH /api/cabinet/settings` требует роль `dev` из серверной NextAuth-сессии
и принимает ровно одно поле: `assistantAiEnabled: boolean` либо
`phoneVerificationPrimaryMethod: 'call'|'sms'`. Ответ содержит только
сохранённое поле. `PUT` общих настроек отвергает оба dev-поля, включая
обёртку `data`, и сохраняет остальные настройки через частичный `$set`.

Регистрация, восстановление пароля и смена телефона отправляют
`POST /api/phone/verify/start` с `method: 'preferred'`. Ответ содержит
`data.method`: `sms` с `status: sms_pending` либо `call` с прежними `id`,
`auth_phone`, `url_image`, `expiresAt`. Запрос без `method` сохраняет звонок.
СМС не требует `callId`; после проверки кода продолжается прежняя установка
пароля/смена телефона. Парольный вход не меняется.

Общий `server/phoneVerification.js` обслуживает `/start` и `/sms/start`:
нормализация телефона, известный flow/город, доступность регистрации и
восстановления, занятость номера, сессия и принадлежность номера при смене.
Прямой `/sms/start` разрешает первый запрос только при приоритете `sms`;
при приоритете звонка остаётся резервным действием после созданного запроса.
При выключенных СМС отправка через этот маршрут запрещена.

Между платными стартами одного `phone + flow` действует общая минута ожидания,
в том числе при смене метода и ошибке провайдера. Переключение и повтор отправки
выполняются только явным действием пользователя. Фоновая проверка звонка
не продлевает ожидание. `startRequestedAt` резервируется атомарно до отправки;
для новой записи используется детерминированный ObjectId по `phone + flow`,
для старой — её `_id`. Конкурирующий старт получает `429`. В отличие от
старого резервного СМС, немедленный переход после звонка также ждёт минуту.
Сбой провайдера не продлевает TTL старого кода. При внешней задержке больше
минуты сохранение защищено CAS по отметке старта; HTTP timeout — 15 секунд.

СМС-код Telefon-IP — четыре цифры, TTL 10 минут, максимум 5 ошибочных попыток.
Хранятся только хеш и соль; после успеха они удаляются. Код, токен и сырой
ответ провайдера не сохраняются в `meta`, не возвращаются и не логируются
при запуске. TTL звонка остаётся 120 секунд, общей верификации — 15 минут.
Запоздалый call polling не записывает результат поверх SMS-запроса; клиент
также игнорирует ответ проверки, начатой до смены способа.

Локальные проверки:

```sh
node --test scripts/phoneVerification.test.mjs scripts/phoneVerification.ui.test.mjs
node --test scripts/actquestAssistantAiSettings.test.mjs
PHONE_TEST_OUTPUT=/absolute/scratch/browser node scripts/phoneVerification.browserHarness.mjs
# В другом терминале, с путями к уже установленным Playwright/Chromium:
PHONE_TEST_OUTPUT=/absolute/scratch/browser PHONE_PLAYWRIGHT_MODULE=/path/playwright/index.mjs PHONE_CHROMIUM_PATH=/path/chrome-headless-shell node scripts/phoneVerification.browser.mjs
```

API-тесты исполняют настоящие обработчики через SWC и настоящий Telefon-IP
адаптер с явным mock fetch. БД заменена моделью в памяти; атомарные MongoDB
операции не проверялись на живом mongod. Браузер использует реальные JSX/CSS,
mock API/сессии и кабинетной оболочки. AuthSplitLayout, Modal и кнопки — настоящие. Настоящие звонки/СМС и production не проверены.
