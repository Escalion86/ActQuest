# HTML мини-сайты ActQuest

Инструмент `/cabinet/admin/mini-sites` принимает готовый ZIP со статическим
сайтом. Раздел доступен из карточки «HTML мини-сайты» в администрировании.
Серверная страница и каждый API допускают только `admin` и `dev` из настоящей
NextAuth-сессии. Модератору, клиенту и гостю API возвращает 403; страница гостя
перенаправляет на штатный вход.

## Использование

1. Указать название (1–100 символов), постоянный slug и ZIP. Нажать
   «Опубликовать мини-сайт». Slug — DNS label: 1–63 символа `a-z`, `0-9`, `-`,
   без дефиса по краям. Переименование slug и удаление сайта не предусмотрены.
2. В карточке доступны адрес, состояние, дата версии/изменения, количество
   файлов и размер, открытие и копирование адреса, замена архива, отключение,
   включение и откат. После замены адрес сохраняется.
3. Откат меняет местами текущую и предыдущую версии; повторный откат возвращает
   другую версию. Откат и замена **сохраняют enabled**. Только явная кнопка
   «Включить» возвращает отключённый сайт в публичную выдачу.
4. При ошибке форма сохраняет введённые данные/выбранный файл. При недоступном
   clipboard показывается предложение скопировать видимый адрес вручную.

Копирование и успешная запись в хранилище не подтверждают доступность адреса.
В этой рабочей копии DNS/TLS/nginx не настраивались, публикации на VPS нет.
Предпросмотра загруженного HTML на origin ActQuest нет.

## Конфигурация процесса Next.js

Нужен Node.js **22.15+** (`node:zlib.crc32`), Linux/POSIX, один локальный
файловый раздел с поддержкой атомарного rename, fsync, symlink и statfs.
Не использовать NFS/объектные хранилища, несколько независимых томов или копии
одного хранилища у нескольких процессов. Несколько workers на **одном**
локальном томе используют одну общую блокировку.

| Переменная | Значение |
| --- | --- |
| `MINI_SITES_ROOT` | Обязательный существующий абсолютный нормализованный путь вне репозитория, например `/srv/actquest-mini-sites` |
| `NEXTAUTH_URL` | Доверенный URL основного приложения; Host и forwarding headers не используются |
| `MINI_SITES_APP_ORIGIN` | Явное переопределение доверенного origin для reverse TLS; вместо NEXTAUTH_URL. Только origin, без произвольного path |
| `MINI_SITES_BASE_DOMAIN` | По умолчанию `actquest.ru`, lowercase DNS domain, без схемы/порта/пути; ссылки всегда HTTPS |
| `MINI_SITES_RESERVED_SLUGS` | Дополнительные запрещённые slug через запятую, например `old-game,partner` |
| `MINI_SITES_QUOTA_BYTES` | Положительное целое, default `524288000` (500 МиБ), общий логический объём **всех** файлов хранилища |
| `MINI_SITES_DISK_RESERVE_BYTES` | Положительное целое, default `209715200` (200 МиБ), свободное место сверх операции |

Root нельзя размещать внутри проекта, делать его предком проекта, `/` или
симлинком; симлинки запрещены и во всех компонентах его пути. Родительские
каталоги должны принадлежать root/UID приложения и не допускать чужой записи
(исключение — системные sticky-каталоги наподобие /tmp). Root и служебные
каталоги должны принадлежать UID процесса Next и не допускать group/world
write. Выделить отдельную Unix-группу для чтения nginx: каталоги `2750` (setgid обязателен), файлы
`0640`, nginx — только читатель. GID корня хранилища задаёт группу чтения:
приложение проверяет тот же GID, setgid и group r-x у каждого существующего
служебного каталога до распаковки, у новых каталогов и файлов и после rename.
Даже при совпадении primary group приложения setgid обязателен. Ошибочные
существующие права/GID не исправляются автоматически: операция закрывается.
Только собственные новые директории получают chmod 2750, файлы — 0640;
chown и изменение системных групп приложение не выполняет. Root создаёт оператор с нужной группой/setgid
до запуска приложения. Preflight оператора: сверить `stat -c "%u %g %a"`
для root и существующих active/staging/states/versions, убедиться в setgid
и group r-x без group/world write; через `id` проверить вхождение nginx worker
в GID root и проход по родительским каталогам, затем проверить чтение ресурса
именно UID nginx. Приложение не может проверить членство внешнего nginx worker.
Приложение не создаёт произвольные корневые пути.
В root не должны писать другие приложения или пользователи. Не помещать туда
секреты и файлы, не относящиеся к этому инструменту. Данные переживают сборку.

Если конфигурация отсутствует или опасна, форма отключается с пояснением,
мутации закрыты. Root проверяется по lstat/realpath/UID/правам. GET не создаёт
каталоги, staging и lock. Ошибки API не содержат абсолютных путей и архивов.

Основной origin должен быть HTTPS (HTTP разрешён только для localhost-стенда).
Публичная зона — валидный DNS domain, всегда HTTPS. Поддомен основного
приложения автоматически резервируется, если находится в выбранной зоне;
он никогда не может стать адресом загруженного сайта. Не используйте схему,
где основное приложение само обслуживает произвольные поддомены.

Встроенно зарезервированы `www,api,admin,cloud,sites,mail,smtp,pop,imap,ftp,sftp,
ssh,ns,ns1,ns2,dns,localhost,static,assets,cdn,auth,login,cabinet,dev,test,staging,
beta,status,support,help,autodiscover,autoconfig,webmail,mx,kronosserver,kronosfinal`.
Дополнительные значения задавать строчными DNS labels. Перед включением
**инвентаризировать все существующие поддомены**, включая regex/wildcard
virtual hosts, и дополнить reserved. Если добавить в reserved уже созданный
slug, API закрывает доступ к нему до устранения конфликта; не менять этот
список без инвентаризации хранилища.

## Лимиты и защита ZIP

- HTTP multipart: максимум `21037056` байт (20 МиБ ZIP + 64 КиБ envelope),
  JSON action: 4096 байт. Реальный поток считается **до** formData/JSON,
  Content-Length дополнительно проверяется, chunked не обходит предел.
- ZIP: `20971520` байт; один файл: `20971520` байт; суммарная распаковка:
  `104857600` байт; максимум 1000 записей, включая каталоги.
- Deadline всей мутации: 30 секунд, включая чтение тела и распаковку;
  учитывается AbortSignal запроса. Ограничиваются фактические распакованные
  байты, а также заявленные размеры; проверяются CRC32 и совпадение размера.
- Перед распаковкой нужно 100 МиБ + 64 КиБ служебного запаса **сверх** резерва
  свободного диска; свободное место проверяется также перед каждым чанком.
- Общая квота учитывает текущие, предыдущие и временные файлы, метаданные и
  остатки после аварии. Для операции дополнительно оставляется 64 КиБ под
  служебные файлы. Квота считает логические байты, свободное место — statfs;
  это не заменяет системные файловые/дисковые квоты.
- Временный пик: прежняя текущая + прежняя предыдущая + новая распаковка.
  Третья версия удаляется только **после** успешного переключения. При нехватке
  места прежняя публикация сохраняется; ENOSPC/EDQUOT возвращают 507.
- Используется явная зависимость `yauzl@3.4.0`, не shell unzip и не парсер
  из Next. Разрешены методы ZIP stored/deflate; шифрование, symlink и special
  files запрещены. Центральный каталог проверяется до извлечения.
- Запрещены zip-slip, абсолютные пути Unix/Windows, backslash, control/NUL,
  `: % ? #`, скрытые имена, пустые/`.`/`..` компоненты, trailing dot/space,
  Windows device names, Unicode не в NFC, пути длиннее 240 символов/16 уровней,
  дубли и коллизии регистра и файл/директория. Все имена проверяются до снятия
  единственной общей папки-обёртки. Нужен точный `index.html`.
- Allowlist расширений: `html htm css js mjs json svg png jpg jpeg gif webp
  avif ico bmp woff woff2 ttf otf eot mp3 wav ogg m4a aac flac mp4 webm ogv mov
  txt xml webmanifest map vtt`. Dotfiles, package/lock/config, `.env`, архивы,
  бинарные исполняемые и серверные исходники других типов запрещены. Исходный
  npm-проект загружать нельзя: нужно заранее подготовить его статический вывод.
  JS не сканируется по словам Node/require. SVG и JS разрешены только потому,
  что выдаются на отдельном origin.

## Хранение, транзакция и восстановление

```
MINI_SITES_ROOT/
  .lock/owner.json              # PID и время, не публично
  staging/<uuid>/public/        # только собственная новая распаковка
  versions/<uuid>/public/       # неизменяемые файлы версий
  states/<uuid>/state.json      # текущее/предыдущее, enabled, имя, статистика
  states/<uuid>/public          # symlink к версии; отсутствует при disabled
  active/<slug>                # symlink к states/<uuid>
```

Никакой каталог кроме `active/<slug>/public` nginx не обслуживает. Состояние
и ссылка public сначала записываются отдельно и синхронизируются. Один rename
новой ссылки `active/<slug>` одновременно фиксирует метаданные и выдачу. Нет
окна, когда disabled уже записан, а nginx видит включённую старую версию.
Новые файлы записываются эксклюзивно, без следования ссылкам из ZIP. Все мутации
защищены глобальным `mkdir(.lock)`, включая создание дубля, enable и rollback.
Конкурент получает 409. Автоперехвата lock по времени нет.

При обычной ошибке убираются только staging, неопубликованная версия/состояние
**данной операции**. После успешной операции сохраняются активная и одна
предыдущая версия; более старая версия и заменённые метаданные удаляются.
Сохранённые сайты не удаляются. При сбое после точки commit новая версия уже
авторитетна; ошибка fsync/очистки попадает в журнал, не делается опасный откат.
Оставшиеся неиспользуемые файлы продолжают занимать квоту.

После SIGKILL/сбоя питания оператор должен:

1. Остановить **все** workers/загрузки этого хранилища и убедиться, что прежний
   владелец lock больше не выполняется (PID может переиспользоваться).
2. Сделать резервную копию **всего** root, сохраняя symlink, права и владельца.
3. Проверить `active/* -> states/*/state.json`, ссылки current/previous и
   соответствующие `versions/*/public`, сверить журнал и `owner.json`.
4. В отдельном окне обслуживания удалить stale `.lock` вручную. Не снимать
   lock только по возрасту. Staging и состояния/версии, не достижимые ни из
   одного active/current/previous, можно убрать после backup и ручной проверки.
   Автоматической сборки мусора после аварии в первой версии нет.
5. Проверить чтение/enable/rollback на тестовом сайте, затем вернуть workers.

Для согласованного backup остановить мутации или сделать snapshot файловой
системы; копировать root целиком, не разыменовывать ссылки. Restore выполнять
вне проекта с тем же владельцем/группой; проверить ссылки до возврата выдачи.
Не создавать несколько независимо записываемых копий одного root.

## Шаблон nginx (оператор применяет отдельно)

До включения: wildcard DNS `*.actquest.ru`, wildcard TLS-сертификат (обычно
DNS-01), инвентаризация поддоменов и их reserved. Основное приложение и
существующие сайты должны иметь свои exact `server_name`; nginx отдаёт им
приоритет перед regex. Проверить порядок **прочих regex** server blocks:
regex выбирается первым совпавшим, их приоритет нельзя считать exact.
Заменить root/сертификат/зону одновременно с серверным конфигом приложения.
Существующие wildcard server_name также имеют приоритет перед regex: их
нужно учесть при инвентаризации. Правила выбора и именованных captures:
[официальная документация nginx](https://nginx.org/en/docs/http/server_names.html).
Не включать snippets приложения, proxy/PHP/CGI/SSI и правила SPA fallback.

```nginx
# Внутри http {}; include mime.types обычно уже есть на уровне http.
server {
    listen 443 ssl;
    # При необходимости также listen [::]:443 ssl;
    server_name "~^(?<mini_slug>[a-z0-9](?:[a-z0-9-]{0,61}[a-z0-9])?)\.actquest\.ru$";
    ssl_certificate     /etc/letsencrypt/live/actquest-wildcard/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/actquest-wildcard/privkey.pem;

    # Защита даже при случайном выборе этого server как default_server.
    # Пустой capture не должен превратить root в active/public.
    if ($mini_slug = "") { return 404; }
    root /srv/actquest-mini-sites/active/$mini_slug/public;
    index index.html;
    autoindex off;
    ssi off;
    # Ссылки active/public созданы приложением; disable_symlinks on запрещён.
    # У nginx только чтение, у посторонних нет права записи в root.
    open_file_cache off; # выключение не сохраняет ранее открытые дескрипторы
    etag off;
    if_modified_since off;
    # Стандартная таблица + mjs (его нет в некоторых mime.types).
    include /etc/nginx/mime.types;
    types { application/javascript mjs; }
    default_type application/octet-stream;
    add_header Cache-Control "no-store" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Referrer-Policy "no-referrer" always;
    add_header Content-Security-Policy "frame-ancestors 'none'; object-src 'none'; base-uri 'self'" always;
    add_header Origin-Agent-Cluster "?1" always;

    if ($request_method !~ ^(GET|HEAD)$) { return 405; }
    location ~ (^|/)\. { return 404; }
    location / { try_files $uri $uri/ =404; }
    # Никаких alias на root, error_page в ActQuest, proxy_pass/fastcgi_pass.
}
server {
    listen 80;
    server_name "~^(?<mini_http_slug>[a-z0-9](?:[a-z0-9-]{0,61}[a-z0-9])?)\.actquest\.ru$";
    if ($mini_http_slug = "") { return 404; }
    if ($request_method !~ ^(GET|HEAD)$) { return 405; }
    # Используется только валидированная regex-capture, не произвольный Host.
    return 308 https://$mini_http_slug.actquest.ru$request_uri;
}
```

Для MIME использовать стандартный `mime.types` на уровне http; убедиться, что
`js/mjs` выдаются как `application/javascript`, `css` как `text/css`, SVG как
`image/svg+xml`, шрифты/медиа — с соответствующими типами. Если локальный
mime.types старый, обновить точечно его таблицу в конфигурации этого server.
Не добавлять динамические обработчики по расширениям. Неизвестный slug и
выключенный сайт не имеют public и получают 404. Загрузка существующей
директории без index может получить стандартный 403; листинга нет. Отключение
прекращает новые запросы; уже скачанные файлы, открытые ответы и зарегистрированные
сайтом Service Workers невозможно отозвать у посетителя серверным rename.

**Изоляция origin:** перед включением проверить, что сессионные/auth cookies
основного ActQuest являются host-only, без `Domain=.actquest.ru` (и без
аналогичного широкого Domain для выбранной зоны). Проверить и другие cookies
авторизации, CSRF, login, reverse proxy и SSO. Поддомены остаются same-site:
SameSite cookies не заменяют Origin/CSRF. Не доверять `*.actquest.ru` в CORS,
postMessage, OAuth redirect и allowlists основного приложения. Не добавлять
CORS response headers мини-сайтам по наследуемому доверию к parent domain.
Мини-сайт может выполнять произвольный браузерный JS; его нельзя считать
доверенной частью кабинета. Не менять auth в рамках установки инструмента:
при несовместимой cookie/CORS-политике сначала отдельно устранить её либо
выделить независимую публичную DNS-зону.

На reverse proxy ActQuest ограничить body (например `client_max_body_size 21m`)
и время загрузки, число запросов/соединений. Это дополнительная защита; API
сам считает фактические байты. Не добавлять выдачу сайтов на origin ActQuest,
через `/public/uploads`, route handler, iframe или API preview.

Перед reload: `nginx -t`, затем ручная проверка TLS и GET/HEAD статического
ресурса, 404 неизвестного/disabled slug, 405 POST, невозможности чтения metadata,
приоритета существующих exact hosts и отсутствия общих auth cookies/CORS.
Этот документ — шаблон, **не свидетельство выполненной настройки сервера**.

## Проверки разработки

Скрипты переносимы: временное хранилище создаётся в `MINI_SITES_TEST_TMP` или
`os.tmpdir()` (учитывает TMPDIR). Evidence — в `MINI_SITES_TEST_OUTPUT` либо
`os.tmpdir()/actquest-mini-sites-evidence`. Они не используют `../tmp` рядом с
репозиторием. Оба пути задавать вне Git; для каждого прогона выбрать отдельный
output, чтобы сохранить прежние доказательства. В sandbox TMPDIR должен быть
коротким абсолютным managed scratch-путём, иначе Chromium SingletonSocket
может превысить лимит Unix socket.

- `npm run test:mini-sites` — настоящие handlers с явной фикстурой сессии,
  настоящее временное хранилище, без БД/.env/VPS. Негативный GID моделируется
  контролируемым lstat; фактические GID, setgid и group r-x/read проверяются
  на настоящих созданных файлах/каталогах, включая вложенные и rename.
  Проверки хранилища требуют Linux/WSL с POSIX-правами; на Windows они
  явно пропускаются, HTTP/auth-проверки продолжают выполняться.
- `npm run test:mini-sites-navigation` — браузерная проверка навигации кабинета.
  Использует локальный devDependency `playwright`; перед первым запуском
  выполните `npx playwright install chromium` или задайте `MINI_SITES_CHROMIUM`
  абсолютным путём к установленному Chromium/Edge. Артефакты пишутся во
  временный каталог ОС, либо в `MINI_SITES_NAV_OUTPUT`, вне репозитория.
- `node scripts/miniSites.browserHarness.mjs` — изолированный сервер на
  127.0.0.1:3293, настоящие JSX/CSS/CabinetLayout/CabinetButton и API handlers,
  admin-сессия — явно названная фикстура. Хранилище настоящее временное.
- `node scripts/miniSites.browser.mjs` — Playwright: 390/1280px, обе темы,
  полный workflow, clipboard/отказ, строгие измерения кнопок и overflow.
  Playwright/Chromium конфигурируются `MINI_SITES_PLAYWRIGHT` и
  `MINI_SITES_CHROMIUM`; адрес — `MINI_SITES_TEST_BASE`, порт стенда —
  `MINI_SITES_TEST_PORT`. В этом окружении использованы заранее доступные
  Playwright из ux kit и Chromium 1243; это не зависимости production.
- Стенд остановить POST `http://127.0.0.1:3293/__stop`: временное хранилище
