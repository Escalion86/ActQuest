# Помощник ActQuest: публичный FAQ и советы в кабинете

## Текущее состояние исходников

Помощник доступен без `testai` на `/`, `/krsk`, `/nrsk`, `/ekb`, `/cabinet`
и обычных дочерних страницах кабинета. Флаг больше не влияет на видимость.
Обычные страницы описания игры, статьи, legacy `/<location>/game/...`,
`/game/.../process/...`, `/game/.../test/...` не включены в разрешённые поверхности.
В кабинете дополнительно исключены сегменты `game-control`, `game-map`,
`photo-review`, `task-preview`, `process`, `test`.

Единственный экземпляр подключён в `app/providers.js`, внутри `SessionProvider`.
Страничные подключения из `app/page.js` и `app/[location]/page.js` удалены.
Виджет использует `usePathname`, не читает `testai` или search params.
При скрытии размонтируется панель, отменяется запрос и восстанавливаются
`--aq-site-audio-right` / `--aq-site-audio-bottom`. Существующий ResizeObserver
и координаты музыкальной кнопки сохранены без конкурирующих Tailwind-отступов.

Исключение помощника из `proxy.js` удалено: авторизованная главная штатно
перенаправляет в кабинет, даже с `testai`. Условия защиты кабинета не менялись;
разрешённые поверхности виджета не используются для предоставления доступа.

В кабинете начальный город берётся только из `session.user.location`, если это
`krsk`, `nrsk` или `ekb`. Без валидного города профиля и всегда вне кабинета
(даже на городской главной и с авторизацией) сначала показывается отдельный
шаг «В каком городе хотите играть?» с тремя кнопками. URL не задаёт город,
резервного Красноярска нет. До выбора скрыты быстрые вопросы, select и форма;
дополнительный guard `ask` запрещает любой запрос `/api/assistant` без города.
После выбора доступны обычная панель и смена города через select.
Служебные подписи FAQ/ИИ удалены: все ответы помечены нейтрально «Помощник».
Приветствие: «Помогу выбрать игру и разобраться с участием.»
При открытии фокус получает контейнер dialog (`tabIndex=-1`), не textarea.
Выбор города, быстрый вопрос и получение ответа не переводят фокус в поле;
ручной тап и Tab доступны, Escape возвращает фокус кнопке открытия.

Диалог существует только в памяти общего mount. Переходы между обычными
страницами кабинета его сохраняют; смена пользователя/статуса сессии,
logout, города сессии или public/cabinet сбрасывает панель и pending-запрос.
Выбор другого города вручную очищает историю, введённый вопрос и выбранную игру.
Переход на исключённую страницу полностью размонтирует панель. Нет сохранения
диалога в cookie, localStorage, sessionStorage или БД.

## Контракт POST /api/assistant

```json
{
  "city": "krsk",
  "question": "Хочу записаться",
  "history": [{ "role": "user", "content": "Как подготовиться?" }],
  "pathname": "/cabinet/games-upcoming",
  "gameId": "123456789012345678901234"
}
```

`city` и `question` обязательны. `history`, `pathname`, `gameId` необязательны.
Города: `krsk | nrsk | ekb`. ID — строго 24 hex-символа без нормализации.
`pathname` — локальный путь длиной до 200 символов, только буквы, цифры,
`/`, `_`, `-`. История содержит только до четырёх вопросов пользователя.
Любые дополнительные поля (`userId`, `user`, `session`, `role`, `teamRoles`
и прочие), неизвестные города, system/assistant history запрещены с 400.

`pathname` — только подсказка поверхности, НЕ право доступа. Реальный route
передаёт в gateway callback `getServerSession(authOptions)`. Только проверенная
серверная сессия разрешает чтение персонального контекста. На главной, без
сессии и без явно выбранной игры персональный reader не вызывается.
`city` фильтрует публичные игры; он не задаёт город/роль/идентичность пользователя.
Город команды/игры читается из БД, идентичность/системная роль — из сессии.

Ответы:

- `success: true, mode: faq` — детерминированная справка, без ИИ;
- `mode: personalised` — серверный read-only совет по выбранной игре, без ИИ;
- `mode: ai` — модель выбрала ID подтверждённых источников, текст собрал сервер;
- `mode: no-data` — данные не удалось проверить либо выбранная публичная игра
  недоступна; это не утверждение об отсутствии команд;
- `mode: policy` — отказ по теме/секретам/личным данным, без ИИ;
- `success: false, mode: unavailable, error` — неверный запрос, лимит,
  отсутствие ключа для свободного вопроса, сбой модели или deadline.

У успешного ответа есть `answer`, `links: [{title, href}]`.
FAQ регистрации/расписания дополнительно возвращает
`games: [{gameId, title, href}]` (до пяти публичных будущих игр), `notice`.
Интерфейс показывает названия игр без «Выбрать:». Перед списком —
«Нажмите на игру, чтобы узнать подробности». Нажатие сохраняет `gameId` и
отправляет «Подробнее об игре». Ответ деталей — только точный server-built
`/game/<gameId>` из безопасных источников `readPublicGames(city).games`:
название, дата/время в часовом поясе города, формат, участие и статус записи.
Стоимость и тарифы предлагается посмотреть в описании — числовая проекция
не позволяет однозначно объяснить условия тарифов. Ссылка — «Открыть игру».
Нет ключа или бюджета — детали продолжают работать без модели и без чтения
сессии/членств. Без gameId предлагается список; отсутствующая игра даёт no-data,
без догадок и ссылки на отсутствующую игру. Последующий «Как записаться?»
использует сохранённый gameId и прежнюю проверенную серверную сессию кабинета.
Ссылки собирает сервер; никаких регистрационных мутаций по нажатию нет.

## Детерминированные сценарии и персонализация

`server/assistant/deterministic.mjs` распознаёт быстрые FAQ, подробности игры
и регистрацию/расписание без вызова модели. Работает без ключа и после исчерпания дневного
бюджета ИИ. Тематический фильтр и строгая схема применяются ДО этой маршрутизации.
Обычные rate/concurrency/body/deadline ограничения сохраняются и для FAQ.

`server/assistant/registration.mjs` использует только read-only MongoDB driver:
не подключает `dbConnectGlobal`, модели с autoIndex, personal-team upsert или
регистрационные endpoints. Пользователь определяется через существующий
`resolveSessionUserFilter`, затем читается только `_id` Users. Fallback
phone/VK/Telegram из серверной сессии используется только в серверном поиске.
Список членств выбирается строго по найденному `userId`, а не по ID клиента.
Роль капитана проверяется по точному `getCaptainRoleQuery`, как в настоящем
POST регистрации (без расширения прав для неканонического `CAPTAIN`).

Выбранная игра читается точным `_id` под тем же строгим публичным фильтром:
`hidden: false`, `isPrivate != true`, public/отсутствующий `orderType`,
`sourceOrderId: null`, `active`, будущая `dateStart`, выбранный публичный город.
Требуется безопасное публичное название. Никаких private/corporate/hidden игр,
заданий, кодов, подсказок, контактов, rich-text или внутренних финансов.

Проверяются ВСЕ обычные команды пользователя, а не первая команда:

- нет обычных команд: создать или присоединиться, запись делает капитан;
- только participant/liaison: попросить капитана, не обещать право записи;
- капитан другого города: нужна команда капитана в городе игры;
- несколько подходящих команд капитана: число и предложение выбрать в штатной форме;
- уже зарегистрирована подходящая команда пользователя: сообщить об имеющейся записи;
- `player`: обычная команда не нужна; существующая индивидуальная регистрация
  определяется по personal-команде владельца в городе игры;
- техническая `personal` НЕ считается обычной командой;
- закрытая запись/заполненный лимит: используется настоящий
  `helpers/gameRegistration.js#getGameRegistrationError`, без admin/manual обхода;
- ошибка БД/неполная идентичность: честный `no-data`, не «у вас нет команд».

Никакие команды, заявки, регистрации, оплаты или индексы не создаются.
Советы ведут только на существующие `/cabinet/games-upcoming`, `/cabinet/teams`.
Финальные права и свободные места повторно проверяет штатная регистрация:
это не бронирование и не гарантия успешной записи. Имена пользователей,
телефоны, email, списки участников, team IDs и user IDs не передаются модели;
персональная ветка вообще не вызывает внешний ИИ. Не возвращаются имена команд.

## Провайдер, безопасность и бюджет

Свободные вопросы используют прежние `DEEPSEEK_KEY`, `server/deepseekClient.mjs`,
`deepseek-v4-flash`. Модель возвращает только `{sourceIds:[...]}`, сервер
проверяет схему/существование/уникальность источников и собирает свои тексты.
Идентичность сессии, `pathname` и `gameId` не добавляются в AI payload.
Публичный `server/assistant/publicGames.mjs` и его safe projection не ослаблены.

Проверка Origin сохраняет публичный HTTPS ActQuest и серверную конфигурацию,
не доверяет клиентским Host/X-Forwarded-Host. Старый `/api/deepseek` не менялся.

Сохранены 8192 байта body, 700 символов вопроса, history 4×500,
15 секунд общего deadline / 18 секунд клиента, DB maxTimeMS 1500,
connection/socket timeout 2000, concurrency 2, 6 запросов клиента/минуту,
20 запросов процесса/минуту. Свободный ИИ по-прежнему ограничен 40 вызовами
и 640000 зарезервированных токенов за 24-часовое окно процесса;
16000 резервируется на вызов, prompt до 15000 UTF-8 байт, output до 256 токенов.
Без retries и возврата резерва после сбоя; счётчики в памяти процесса.

Это не распределённый бюджет. Перезапуск сбрасывает счётчики, несколько
процессов имеют отдельные лимиты. Увеличение бюджета НЕ выполнено.
